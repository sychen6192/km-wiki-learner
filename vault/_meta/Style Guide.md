# Style Guide — vault 憲法

這份文件是人與 agent 共同遵守的規範。`tools/vault.py lint` 會機械式檢查其中可檢查的部分。

## 資料夾

| 資料夾 | 用途 | frontmatter |
|---|---|---|
| `Notes/` | 原子概念筆記（evergreen 目標形態） | 必填 |
| `Maps/` | Map of Content，一個領域一張 | 必填 |
| `Sources/` | 單一來源的濃縮摘要（文章／論文／repo／影片） | 必填 |
| `Raw/` | **不可變的原始素材層**：人類（或工具）丟進來的網頁剪藏、論文、文字檔。agent 只讀不改 | 免 |
| `Daily/` | 迴圈每日報告 `YYYY-MM-DD.md` | 免 |
| `Review/` | 複習卡（`Flashcards.md`，spaced-repetition 格式） | 免 |
| `_meta/` | 規範與模板，**不參與知識圖**（scan 會跳過） | 免 |
| 根目錄 | `Home.md`（儀表板）、`Inbox.md`（人類指令佇列） | 免 |

## Frontmatter 欄位（Notes / Maps / Sources）

```yaml
---
status: seed | budding | evergreen   # 必填：佔位 → 有骨架 → 可長期引用
created: YYYY-MM-DD                  # 必填
updated: YYYY-MM-DD                  # 必填：每次實質修改要更新
tags: [concept, ...]                 # 建議
aliases: [縮寫或同義詞]               # 選填：讓 [[別名]] 也能解析
review_after: YYYY-MM-DD             # 選填：下次複習日（間隔遞增 7 → 21 → 60 天）
sources:                             # 選填：主要依據的來源清單（網址或 vault 內路徑）
  - https://...
source_date: YYYY-MM-DD | unknown    # Sources/ 必填：來源自己的最後更新日
locked: true                         # 選填：人類宣告此頁禁止 agent 改寫
---
```

## Raw 消化契約

一個 `Raw/` 檔案「已消化」的定義：**存在一篇 `Sources/` 筆記以 wikilink 引用它**（例如 `[[某剪藏]]` 或 `[[paper.pdf]]`）。`vault.py scan` 依此列出 `pending_raw` 待辦。消化 = 為它寫一篇 Source 摘要 + 把觀念織進相關概念筆記，原始檔案本身永不修改、永不刪除。檔名以 `_` 或 `.` 開頭的檔案不算素材。

## 筆記寫作規則

1. **一頁一概念**，標題即概念名。技術名詞用英文原文當標題（連結目標才穩定），內文預設繁體中文。
2. **長度 150–400 字**。塞不下就拆頁；不足就標 `seed`。
3. **至少 2 條出鏈**（`[[wikilink]]`），並被至少一張 Map 收錄。連結要編進句子裡，不要只堆在文末。
4. **允許引用不存在的頁面** — dangling link 是本維基的生長機制（知識前緣），但引用時必須是你真心認為值得成頁的概念。
5. **事實要有來源**：外部知識在 frontmatter `sources` 或內文附網址；不確定的內容明白標註「不確定」。
6. **改寫要克制**：更新既有筆記時做增量編輯，保留人類手寫的段落；`locked: true` 的頁面完全不碰。
7. 第一行之後直接進入定義句：「**X** 是……」，讓預覽卡片與 graph hover 立刻可讀。

## 來源時效（Sources/ 必守）

摘要一份來源時，除了「它說了什麼」，還要記下**它本身有多新**。理由很實際：
過期的文件看起來跟現行的一樣權威，而讀者（包括未來的你）沒有線索可以分辨。

- frontmatter 加 `source_date`：**來源自己的最後更新日**，不是你讀它的日期。
  來源沒有標日期就寫 `unknown` —— 空著等於宣稱「我查過而且很新」。
- 內文第一行註明來源身分：標題、出處（系統／網站）、作者（若有）、`source_date`。
  內部文件另外記可回溯的 ID。
- **`source_date` 超過一年或是 `unknown`** → 摘要開頭加一行醒目提示：
  `> ⚠️ 此來源最後更新於 YYYY-MM，內容可能已過期。`
- 引用它的概念筆記要**繼承這個限制**：容易變動的細節（版本號、路徑、排程時間、
  負責人、數量級）不要寫成肯定句，改成「依 [[某來源]]（YYYY-MM）當時的描述……」。
- **多份來源互相矛盾時兩說並陳並各自標日期**，不要自己挑一個當真相 ——
  尤其是內部知識庫，三年前的架構圖通常還掛在上面。
- 原則：**過期不是問題，假裝不過期才是。**

## 狀態晉升標準

- `seed`：只有佔位與問題，等待迴圈養大。
- `budding`：有正確的定義與骨架，出鏈齊備，但缺深度或例子。
- `evergreen`：定義準確、有洞見或對照、來源可信，可被其他筆記長期引用。降級也允許（發現內容過時）。
- 全部事實都來自 `source_date: unknown` 或超過一年的來源時，**最多只能到 `budding`** ——
  無法驗證時效的內容不該被別的筆記當長期引用基礎。

## 語言學習筆記（日本語 N4 等）

語言領域的內容形狀跟概念筆記不同，額外規則：

- **一個文法點一頁**，標題用**不帶波浪號**的形式（`なければならない`，不是 `〜なければならない`）——
  全形 `～` 與波浪線 `〜` 是不同字元，帶了就容易連結失效。內文再寫 `〜` 沒關係。
- 文法筆記的骨架：**意思 → 接續（表格）→ 例句 → 口語變化 → 容易搞混的鄰居**。
  「鄰居」那節要連到意思相近或相反的句型，這是語言學習最容易失分的地方。
- **單字不要一個字一頁**。單字進複習卡（`Review/<領域> 複習.md`），只有值得展開的
  （多義、易混淆、文化背景）才單獨成頁。
- **漢字**同理：規律與易混字成頁，個別字進卡片。
- **講義與作業**每份一篇 `Sources/` 摘要：教了哪些文法點（連到各自的頁）、
  出現的新單字、作業考什麼、我錯在哪。錯題特別重要，那是複習的重點來源。
- 一份講義的消化算**一個工作項**，即使它產出多篇文法筆記。

## 複習卡規則（Review/Flashcards.md）

- 單行卡：`問題::答案`，一張卡考一個概念，答案一句話。（多行卡用單獨一行的 `?` 分隔，牌組用 `#flashcards/子牌組` 標籤。）
- **雙向卡用三個冒號** `正面:::背面`：外掛會同時考正反兩個方向，適合單字（`薬:::藥`）。
- 一個領域一個複習檔（`Review/日本語 N4 複習.md`），檔頭放該牌組的 `#flashcards/子牌組` 標籤。
- 每篇新筆記至少配 1 張卡，放進對應主題小節，問題盡量帶 `[[來源筆記]]` 連結。
- 卡片是給人腦的：考「為什麼／差異／取捨」，不考背誦細節。
- **絕對不要動 `<!--SR:...-->` 註解** — 那是 spaced-repetition 外掛的排程狀態（下次複習日／間隔／難度），改寫或刪除等於清除使用者的複習進度。修改既有卡片文字時，保留卡片尾端的 SR 註解原樣。
